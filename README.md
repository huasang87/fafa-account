# Fafa 的账本 · 3.0

儿童零花钱账本：赚钱任务、买东西、收支记录，以及一个带照片的储蓄愿望。无构建步骤，继续使用现有 GitHub Pages 和 Firebase 项目。

## 本次功能

- 洗脸刷牙每周 10 次、每次 2 元；洗澡每周 5 次、每次 4 元。所有任务每周一更新。
- 3.0.2 新增游泳：每次 6 元、每周最多 2 次；攀岩课改为每次 6 元、每周最多 1 次。旧流水保持原金额，不重新计价。
- 3.0.1 将两项日任务改为周任务：沿用现有本周任务计数，不重新结算流水或清空账目；跨天不再重置，下周一统一归零。
- 大任务按钮、紧凑的首页愿望入口、绿色「已攒够」文字角标。
- 愿望支持照片、名称、价格、编辑和移除；达标只提示，不自动消费。
- 完整的购买记账、手动收支、记录、空状态、确认和反馈界面。
- 支持两位小数。照片转为 JPEG，最长边 800px，完整 data URL 不超过 80 KiB。

## 数据保护

1. 继续使用 `users/fafa_main_account`；不删除文档、不覆盖原来的 `history`。
2. 账目继续用稳定 ID 和 `recordEvents` 追加事件。使用事务读取最新数据后合并，旧事件不重复上传。
3. `wishState` 是独立字段；修改/移除愿望不改余额、流水和任务进度。
4. 首次打开先把本机旧键的原始字符串备份至 `fafaBackupBeforeV3`。新账本作为单个 JSON 原子写入 `fafaAccountV3`，旧版键保持原样。备份或解析失败时停止写入。
5. 同步期间新增的本机记录会再次合并，网络错误时保留本机数据。离线提示不表示已同步到云端。
6. 记录页提供完整 JSON 导出（包括软删除记录和升级前备份）。清空操作仍需原有家长密码，先本地快照及导出，再写软删除标记；发布和测试不执行真实清空。
7. 云端累计数据接近 850 KB 时停止云端写入并保留本地内容；请导出备份后安排归档扩容。现有单文档模型并非无限容量。

`fafaBackupBeforeV3` 是每台设备自己的备份。服务器导出无法包含另一台设备尚未同步的记录，请保留设备浏览器数据，等待显示「云端已同步」。旧前端密码仍仅是防误触措施，并非服务端登录。

## 本地验证

```sh
npm test
npm run preview
```

打开 `http://127.0.0.1:4173/?preview=1`。预览使用单独的 sessionStorage 示例账本，不加载 Firebase；预览服务器也通过 CSP 禁止云端网络连接。测试不得在真实页面记测试账、清空记录或修改愿望。

## 发布与回退

发布前在仓库外保留 Git bundle、旧源码 ZIP、Firestore 原始 JSON 以及 SHA-256 清单。私人账本备份禁止进入 Git。

GitHub Pages 使用根目录入口。旧 `fafa-account-firebase-safe/` 入口跳转到根目录，避免维护两个不同版本。

需要回退代码时，先从新版导出当前完整账本，并保留 `fafaAccountV3`；旧版本不会读取新版专用本地键，因此不要在有离线新账的情况下直接切回旧版。仅回退静态文件，不恢复/覆盖云数据库。账目恢复必须逐 ID 合并并先另做备份。
